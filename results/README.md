# Первые измерения доли попаданий

Полное исследование: [отчёт с графиками](full/report.md), 6 975 прогонов,
155 конфигураций из одного–трёх уровней, отдельные train/validation-наборы.
Команда повторения из корня: `python3 scripts/run_research.py`.
Этот файл ниже описывает предварительный baseline из 90 прогонов.

`baseline.csv` содержит 90 прогонов: 6 нагрузок × 3 ёмкости × 5 одноуровневых политик.
Каждый прогон начинается с пустого кеша. Число запросов — 10 000.
Идеальный результат рассчитан один раз для каждой пары «нагрузка, ёмкость».
Время выполнения не измеряется.

В `baseline_manifest.json` записаны параметры, описание нагрузок, seed, версия Python,
ревизия Git и SHA-256 исходников и входных файлов. Файлы в `data/research` содержат
точные последовательности. В их заголовках ёмкость равна 8; в CSV прогоны с ёмкостями
16 и 32 используют те же ключи с изменённым первым числом заголовка.

`hit_ratio` и `ideal_hit_ratio` — доли от 0 до 1.
`hit_gap = ideal_hits - hits` — число потерянных попаданий.
`gap_pp` — разница долей попаданий в процентных пунктах.

Например, воспроизведение строки ARC для uniform_64 и ёмкости 8:

```bash
./build/cache_sim configs/arc.cfg --compare < data/research/uniform_64.in
```

Это предварительный контрольный набор, а не окончательное исследование.
Для случайной нагрузки использован только один seed (42); перед выводами нужны
дополнительные seed, другие параметры и сравнение многоуровневых конфигураций.
