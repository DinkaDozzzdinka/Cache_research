## Что хранится

Уровень содержит три списка ключей и одну хеш-таблицу:

- `A1in` — реальные страницы, порядок FIFO. Новые ключи попадают в начало, вытесняем с конца.
- `Am` — реальные страницы, порядок LRU. Попадание перемещает ключ в начало.
- `A1out` — история ключей, вытесненных из `A1in`, без объектов страниц.

У каждого ключа одна запись `Entry`. Она содержит указатель на страницу, название очереди
и итератор узла списка. В истории указатель пустой. Реальная страница одного уровня
находится только в `A1in` или `Am`. Размер уровня — сумма размеров этих двух списков.

В статье есть и упрощённая, и полная версия.
Мы реализуем полную: попадание в `A1in` НЕ переводит страницу в `Am`.
Переход в `Am` происходит при загрузке ключа, который ещё находится в `A1out`.

В конструкторе выбираем порог `Kin = max(1, capacity / 4)` при ненулевой ёмкости.
выбираем лимит истории `Kout = max(1, capacity / 2)` при ненулевой ёмкости.


`splice` сохраняет итератор на перенесённый узел. После переноса между очередями
итератор `key_it` всё ещё указывает на тот же узел, но уже в другом списке.


Почему выбираем жертву ДО вставки: входящая страница не должна сама стать жертвой этой вставки.
Почему сначала подготавливаем новую страницу: при ошибке её копирования или выделения памяти
старый кеш ещё можно сохранить. Почему колбек вызывается в конце: к этому моменту списки, таблица и размер уровня уже согласованы.

Проверка `am_.empty()` нужна для первоначального заполнения и малых ёмкостей.
Например, при ёмкости 1 размер `A1in` равен `Kin`, но пустая `Am` не содержит жертвы.
В таком случае вытесняем из `A1in`. При непустой `Am` и `|A1in| == Kin`
выбираем жертву из `Am`, как в псевдокоде статьи.

## Что такое unique_ptr

`std::unique_ptr<T>` владеет одним отдельно созданным объектом `T`.
`std::make_unique<T>(page)` выделяет память и создаёт копию `page`.
При уничтожении указателя объект удаляется автоматически: вручную `delete` писать не нужно.
`reset()` удаляет объект и делает указатель пустым. В записи истории остаётся только
пустой указатель вместе с остальными метаданными, без выделенного объекта `T`.
Это также позволяет использовать страницы, у которых нет конструктора по умолчанию.

У каждой реальной страницы есть отдельное выделение памяти. Это сознательная плата
за один общий индекс для реальных страниц и истории без хранения объекта `T` в истории.

`extract` не равен вытеснению. У нас он нужен для переноса страницы в L1,
поэтому удаление реальной страницы через `extract` не создаёт запись `A1out`.
После извлечения всех реальных страниц `empty()` возвращает `true`, даже если история не пуста.


Инварианты после успешного публичного вызова:

1. Один ключ принадлежит ровно одному из трёх списков и имеет одну запись таблицы.
2. `key_it` указывает на узел ключа именно в списке, указанном в `queue`.
3. В `In` и `Main` указатель на страницу непустой, в `Out` — пустой.
4. `size() <= capacity()`, длина истории не больше `Kout`.
5. Повторная вставка реальной страницы отвергается; попадания обрабатываются через `touch`.

Копирование входящей страницы и создание записи выполняются до удаления старой страницы.
Тесты проверяют восстановление после исключения при копировании новой страницы и загрузке ghost.
Если исключение бросит пользовательский колбек, текущий уровень уже завершил вытеснение.
Отката всей иерархии здесь нет. Как и в остальных кешах, полная гарантия для произвольных
пользовательских типов с бросающим хешированием здесь не заявляется.

## Подключение к проекту

В `cache_level.hpp` подключён `two_q.hpp`.
В конструкторе ветка `Policy::TWO_Q` создаёт `TwoQCache<T, KeyT>` через `variant::emplace`.
В `touch`, `extract`, `insert`, `size` добавлены такие же ветки, как для LRU и LFU:
`std::get_if` возвращает указатель на активный кеш 2Q или `nullptr`.
Непустой указатель позволяет вызвать соответствующий метод. После вставки нужен `return`,
чтобы не дойти до исключения об отсутствии активной политики.
В список типов `variant` добавлен `TwoQCache<T, KeyT>`.
Неподдерживаемыми пока остаются ARC и LIRS.

Парсер уже умел читать строку `2Q`, поэтому менять enum и `ReadConfig` не понадобилось.
В CMake добавлен `tests/two_q_test.cpp` в исполняемый файл тестов.
В тесте неподдерживаемых политик `TWO_Q` удалена из списка ожидаемых ошибок.
Общие проверки страниц со строковыми данными и нулевой ёмкости теперь запускаются и для 2Q.

`configs/two_q.cfg` содержит один уровень `2Q`.
`configs/mixed_2q.cfg` содержит три уровня: `2Q LRU LFU`.
Число в первой строке — количество уровней, следующая строка — их политики.

В иерархии реальные страницы остаются эксклюзивными: на нескольких уровнях одновременно
нет одной и той же страницы. Ключ в истории верхнего уровня при этом может соответствовать
реальной странице нижнего уровня. Это полезная локальная история, а не дубликат данных.
Если страницу нашли внизу, её сначала извлекаем, затем вставляем в L1.
Если в L1 сохранился её ghost-ключ, вставка в L1 направляет страницу в `Am`.

## Запуск и ручной пример

```bash
cmake --build build -j2
ctest --test-dir build --output-on-failure
printf '3 9 1 2 3 4 1 1 5 6 1\n' | ./build/cache_sim configs/two_q.cfg --compare
./build/cache_sim configs/mixed_2q.cfg --compare < data/requests.in
```

Для первого примера ожидается:

```text
hierarchy_hits: 2
ideal_hits: 3
```
